# Linux Compatibility - Implementation Status

This is a concrete audit of what is implemented vs tested vs missing. Status: **IMPLEMENTED**, **PARCIAL**, **NÃO IMPLEMENTADO**, **NÃO VALIDADO**.

## Summary
- **Working well**: SYSCALL entry/dispatch, translated file operations including legacy `open`/`unlink`, `openat` access/create flags, per-descriptor CLOEXEC through pipe/dup/fcntl/execve, anonymous mmap/munmap/mprotect/brk subset, process identity and credential queries, clocks/sleep, arch_prctl TLS, limited clone/fork/execve/wait4, and private futex WAIT/WAKE/WAIT_BITSET/REQUEUE subsets. Freestanding ET_EXEC Linux probes, a static musl libc smoke (256 KiB allocation/free, CPUID-aware `getrandom`, `uname`, time/monotonic clocks, `sched_yield`, `getcwd`, `prctl`, buffered stdio file I/O, `stat`/`fstat`/`access`, directory iteration) and static musl pthread tests (caller stack; default stack; four threads with mutex/join and condition-variable broadcast/join) pass in QEMU with SMAP and a four-vCPU configuration. This is limited evidence, not full Linux compatibility.
- **Major gaps**: PT_INTERP/dynamic linking, broad syscall coverage, signals and signal-aware wait statuses, process groups/SIGCHLD/resource accounting, futex extensions (shared/robust and broader WAIT_BITSET/REQUEUE race coverage), full clone semantics, broad condvar/requeue race and large-thread stress, demand paging/COW/file-backed mmap, vDSO/auxv completeness, concurrent mmap permission changes and remote TLB shootdown, cross-CPU thread migration validation.
